# S3 and existing infrastructure

## Recommended boundary

Use a dedicated bucket or dedicated prefix behind a dedicated artifact hostname.
The bucket uses Block Public Access and ACLs disabled. Publishers authenticate to
S3 using AWS credentials; CloudFront authenticates origin reads using OAC; viewers
have neither credential set.

Use the **regional S3 REST endpoint**, not an S3 website endpoint, for private OAC
hosting. CloudFront's public HTTPS URL serves the encrypted HTML. Basic Auth/VPN
must not cover this viewer route if outside recipients are supposed to use only
an artifact password. Leave the existing internal route protected.

The reference [Terraform](../examples/terraform/aws/README.md) creates a new bucket.
Do not point it at a production bucket hoping it will automatically adopt it.
Importing/adapting existing infrastructure is a separate reviewed operation.

## Publisher permissions

The Terraform output `publisher_policy_json` limits the publisher to:

- `s3:ListBucket`, constrained to the configured prefix;
- `s3:GetObject`, for metadata/head access;
- `s3:PutObject` and `s3:DeleteObject`, limited to that prefix.

Attach the reviewed policy to an existing role/identity. The example does not
create users, access keys, broad admin permissions, or an automatic trust policy.
Use short-lived role/SSO credentials where available. Viewers do not receive this
policy. A publisher can intentionally upload public content, so treat write
access as a sensitive capability, not as mere access to ciphertext.

An existing SSE-KMS bucket needs compatible KMS policies for both the publisher
and CDN origin as applicable. The minimal example uses S3-managed server-side
AES256 encryption to avoid implying that KMS is configured for you.

## Object layout

```text
s3://my-exhibit-artifacts/exhibit/
  exhibit-<opaque-id>.html
  weekly-review.html
  doctor-<random-id>.html       # transient, marked as probe; normally removed
```

There are no public manifests, original Markdown uploads, raw assets, or cloud
password files. Metadata includes format/kind/type, protection state, creation and
update dates, and a digest of the uploaded viewer bytes. Listing reads S3 pages
and recognizes only this format. An empty filtered page may still have a cursor.

`remove` affects one exact current object. It does not recursively delete the
bucket/prefix and does not purge old S3 versions. A failed diagnostic cleanup
reports its exact non-sensitive key.

## Delivery headers

The publisher sets `Content-Type: text/html; charset=utf-8`,
`Content-Disposition: inline`, and `Cache-Control: no-store, max-age=0` on the object.
The CDN supplies CSP, no-referrer, nosniff, noindex/nofollow, and outer-frame denial.
Do not override HTML with `attachment` or `application/octet-stream`.

Do not enable CORS simply because this is an S3 application. The recipient loads a
same-route HTML page and decrypts it locally; there is no cross-origin S3 API call
in the viewer. CORS is not an access-control replacement.

## Connection validation

`doctor` performs a signed prefix listing. `doctor --probe` additionally checks
upload, exact public bytes, inline delivery, headers, duplicate-write rejection,
stale-overwrite rejection, stale-delete rejection, and cleanup. Header differences
are warnings because some deployments intentionally use equivalent policies; a
human must review them.

See [Configuration](configuration.md) for avoiding a doubled prefix and
[CloudFront](cloudfront.md)/[Fastly](fastly.md) for origin authentication.
